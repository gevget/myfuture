# MASTER PROMPT ДЛЯ CODEX — ЛЕНДИНГ «МОЁ БУДУЩЕ / ИИ-НАВИГАТОР»

Ты работаешь внутри папки проекта, где уже лежат исходные материалы: PDF-презентация, подробный MD-файл с описанием проекта, логотип и несколько PNG-иллюстраций с детьми/объектами в фирменном 3D-стиле. Твоя задача — не пересказать материалы, а на их основе спроектировать и реализовать законченный презентационный лендинг проекта.

## 0. СНАЧАЛА ИЗУЧИ ИСХОДНИКИ

Перед любой версткой:

1. Найди и изучи все PDF, MD, PNG/JPG/WebP/SVG в корне и подпапках проекта.
2. Из PDF изучи не только текст, но и визуальную систему: композицию, пластику иллюстраций, палитру, плотность, типографику, характер плашек и иконографики.
3. Из MD возьми полное смысловое ядро: механику, аудитории, двухконтурную архитектуру, дорожную карту, уже сделанное, поддержку, команду, эффекты, пилот.
4. Из картинок выдели канон иллюстраций: персонажи, пропорции, материалы, свет, пастельные оттенки, glow, визуальные метафоры.
5. Не придумывай факты, цифры, партнеров, интеграции или статус проекта, которых нет в исходниках.
6. Если источники противоречат друг другу по второстепенной цифре, не размножай конфликт. Для публичного лендинга используй более нейтральную формулировку. Например вместо 5–15 и 10–15 лет можно писать «горизонт до 15 лет».
7. Все цифры экономического эффекта, которые в презентации обозначены как оценочные или требующие подтверждения на пилоте, не выдавай за доказанный результат.

Только после изучения материалов переходи к реализации.

# 1. ГЛАВНАЯ ЗАДАЧА САЙТА

Это НЕ сайт для родителей и НЕ детский образовательный лендинг.

Primary audience:
- региональные органы власти;
- муниципалитеты;
- профильные министерства;
- институты развития;
- потенциальные инвесторы;
- крупные предприятия;
- ВУЗы и СПО;
- банки и партнеры;
- образовательные организации как участники экосистемы.

Ребенок — центр модели продукта, но НЕ адресат сайта.

Сайт должен восприниматься как интерактивная презентация проекта, которую можно открыть:
- губернатору;
- министру;
- инвестору;
- промышленному предприятию;
- руководителю ВУЗа;
- институту развития;
- партнеру по пилоту.

Главный вопрос лендинга:

> Как регион может увидеть свой будущий кадровый потенциал за годы до того, как кадровый дефицит превратится в кризис?

Главная смысловая цепочка:

**ребёнок → образование → профессия → экономика территории**

Ключевое позиционирование:

**«Моё Будущее / ИИ-Навигатор» — цифровая платформа ранней диагностики склонностей школьников и кадрового прогнозирования для территорий.**

# 2. ФОРМАТ И ВПЕЧАТЛЕНИЕ

Сайт должен быть:
- светлым;
- современным;
- технологичным;
- дружелюбным, но не детским;
- институционально убедительным;

- удобным как полноценная digital-презентация;

- полноэкранным и эффектным на 1920×1080;
- без перегруженной «госуслуговой» эстетики;

Ключевой характер:

То есть визуальный мир проекта сохраняет доброту и optimism исходных 3D-иллюстраций, но сам интерфейс должен выглядеть как серьезный стратегический продукт для государства, бизнеса и инвесторов.

# 3. ТЕХНОЛОГИЧЕСКИЙ ПОДХОД

Сначала проверь текущий проект.

Если репозиторий уже содержит рабочий frontend stack — сохрани его и не переинициализируй проект без необходимости.

Если проект пустой:
- Vite;
- React;
- TypeScript;
- современный CSS с design tokens через CSS variables;
- допускается Tailwind только если он уже установлен или если его использование реально ускоряет разработку без потери качества;
- никаких тяжелых UI frameworks.

Иконки:
- использовать **Phosphor Icons**;
- для React — `@phosphor-icons/react`;
- основной вес `regular`;
- местами `duotone`;
- не использовать emoji вместо UI-иконок.

Анимации:
- CSS transitions / IntersectionObserver;
- либо Framer Motion, если библиотека уже есть или ее подключение оправдано;
- никаких тяжелых WebGL/Three.js решений.

Не подключать зависимости ради одной мелкой функции.

# 13. SECTION 05 — КАК РАБОТАЕТ СИСТЕМА

ID:
`how-it-works`

Eyebrow:
**Механика**

H2:
**От короткого опроса — до кадрового прогноза территории**

Сделать 6-step timeline.

### Шаг 1. Сбор
Класс проходит короткие адаптивные игровые сценарии.

### Шаг 2. Личный результат
Ребёнок получает собственный результат в приватном формате.

### Шаг 3. Агрегация
Для внешней аналитики формируются групповые срезы: класс, параллель, школа, территория.

### Шаг 4. Дополнение
По мере развития подключаются разрешённые образовательные источники: успеваемость, дополнительное образование и другие сигналы.

### Шаг 5. Анализ
ИИ выявляет устойчивые тенденции и динамику групп.

### Шаг 6. Прогноз
Регион, образование и бизнес получают различные уровни агрегированной аналитики.

После timeline сделать раскрывающийся блок:
**«Интеграции по этапам»**

Содержание:
- ядро: собственные данные платформы;

- далее: ВУЗы, СПО, предприятия, государственные программы на уровне агрегированных прогнозов;

Карту тенденций по территории, кадровый прогноз, динамику профилей и основу для планирования образовательной и кадровой инфраструктуры.

Агрегированный прогноз по профессиональным направлениям и территории, который может использоваться при планировании долгосрочной кадровой подготовки.

Прогноз структуры будущего образовательного спроса по направлениям и территориям.

Внедрение в образовательные организации требует административной поддержки, понятного процесса и минимальной дополнительной нагрузки на школы.

- оценочные гипотезы.

Правило:
критически важная информация всегда видна сразу.
Accordion прячет только detail-level information.

---

# 31. ДОСТУПНОСТЬ

Обязательно:

- semantic HTML;
- один H1;
- правильная hierarchy H2/H3;
- `aria-expanded` у accordions;
- accessible mobile menu;
- focus states;
- keyboard navigation;
- контраст текста;
- alt для реальных изображений;
- decorative images `alt=""`;
- buttons не маскировать под links и наоборот;
- tap targets минимум 44px.

---

# 32. PERFORMANCE

Цель:
быстрый презентационный сайт.

Сделать:
- responsive images;
- `loading="lazy"` ниже hero;
- hero asset preload только если реально используется;
- WebP/AVIF при возможности, но не уничтожать исходники;
- code splitting только если оправдан;
- минимизировать JS-анимации;
- никакой тяжелой chart library ради пары графиков;
- layout без CLS;
- SVG/CSS для простых диаграмм.

# 33. SEO / META

Не добавлять выдуманный адрес сайта.

# 34. CONTENT RULES

Текст сайта на русском.

Тон:
- уверенный;
- человеческий;
- институциональный;
- без канцелярита;
- без стартап-жаргона;
- без «революционный / уникальный / меняем мир»;

# 36. MOBILE UX — ОТДЕЛЬНО ПРОВЕРИТЬ

Mobile — не «уменьшенный desktop».

На 390px:
- hero визуал после текста;
- metrics 2+1 или вертикально;
- tabs горизонтально прокручиваются;
- timeline вертикальный;
- dashboard адаптируется, а не уменьшается до нечитаемого;
- команда одной колонкой;
- CTA full-width;
- accordions удобно нажимаются;
- длинные формулы/цепочки переносятся;
- не должно быть horizontal overflow;
- изображения не обрезают лица;
- decorative glows не закрывают текст.

Header menu:
- закрывается после выбора anchor;
- блокирует body scroll;
- поддерживает escape.

---

# 37. DESKTOP / FULL HD

На 1920×1080 сайт должен выглядеть как digital presentation.

Не оставлять контент узкой колонкой 1100px по центру с огромными пустыми полями.

Использовать:
- max-width около 1520px;
- крупную типографику;
- большие визуалы;
- асимметрию;
- широкие схемы;
- fullscreen rhythm.

Но текстовые строки ограничивать по читаемости:
около 700–850px максимум для paragraph blocks.

Он не должен создавать впечатление, что у проекта уже есть реальная статистика региона, если ее нет.

# 43. ФИНАЛЬНЫЙ WORKFLOW

Работай автономно.

1. Изучи файлы.
2. Кратко зафиксируй для себя дизайн-систему и смысловые ограничения.
3. Посмотри текущую кодовую базу.
4. Спроектируй component structure.
5. Реализуй мобильную версию.
6. Расширь до tablet/desktop.
7. Добавь interaction.
8. Проверь контент против источников.
9. Сделай QA.
10. Запусти production build.
11. Исправь все ошибки.
12. В финале дай краткий отчет:
   - что сделано;
   - какие assets использованы;
   - какие visuals оставлены placeholders;
   - какие файлы были изменены;
   - какие места требуют финальной замены изображений/контактов.

Не спрашивай подтверждение по каждой мелочи.
Не останавливайся после scaffold.
Не делай только «первый экран».
Нужно довести лендинг до полностью работающего состояния.

Главный ориентир результата:

**не “детский сайт про профориентацию”, а серьёзная, современная, светлая digital-презентация инфраструктурного проекта о кадровом будущем региона — с человеческим и узнаваемым визуальным языком «Моё Будущее».**
